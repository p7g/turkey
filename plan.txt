Roadmap, in order. Rationale kept short; open questions are the point.

1. base language
   Done through M9.

2. fix papercuts
   Done, and by two different milestones.
   - injectivity. M10b repaid the first half: an unannotated function that
     iterates and then pattern-matches the element no longer needs an
     annotation, because a scheme may carry the equation (delta 39). test.tl's
     `exec` infers `[Item a ~ Instr, Iterator a] fun(a) -> Int` with no
     annotation at all, and the comment there claiming otherwise was false
     until it was corrected.

     The second half was the error message. It now names the remedy -- and
     the remedy changed with the first half: not "add a type annotation" but
     add the equality to the context, which the message prints in full
     (`Add 'Elem c ~ Int' to the context.`).

     Non-injectivity itself is unchanged and still deliberate. Two family
     applications unify only when they are syntactically the same
     application; that is the one thing a functional dependency would have
     bought, and it is still not bought.

3. modules
   Done, M11a/b/c. Moved ahead of the rest because it was already blocking:
   the prelude claimed seventeen ordinary names (add sub mul div rem neg eq ne
   lt lte gt gte show iter next print write) and a user program could not
   define any of them -- M9 hit this on `add` and worked around it by
   renaming.

   The count is twenty now, not seventeen: M12a added map, pure and bind by
   exporting Functor/Applicative/Monad unqualified, which was a deliberate
   ergonomic choice with a stated cost (delta 45). `map` is the one a program
   is most likely to want back.

   Answered: instance coherence. Global uniqueness plus an orphan rule --
   an instance must be declared by the module that declares its class or the
   one that declares its head constructor (delta 43).

4. `?` as general bind
   Not do-notation: `?` is Rust's, generalized past Result. Option, Either,
   List, and eventually a Beam-shaped query monad. Ambient effects do not
   make it redundant -- the abstraction is over data, not over effects.

   Settled: `?` is sugar for `bind` plus a lambda, and must behave identically
   to writing that out. Mutable variables crossing a `?` therefore get closure
   capture semantics, which are already correct. The List case --
   continuation invoked many times, mutable locals shared across branches --
   is not ambiguous; the meaning is whatever the instance's bind does. The
   use case is questionable, which is not a reason to refuse it.

   Scoping: `do { ... }` introduces a monadic context explicitly, and the body
   of any function whose return type is monadic is implicitly a do block. So
   `?` needs no ceremony in the common case and `do` is there for the nested
   or local one.

   Settled, from that rule:
   - A `?` in the body is what raises `Monad m` on the return type. Not "the
     return type has a Monad instance" -- that is not known during generation,
     and it would be non-monotonic in the instance table: adding
     `instance Monad Array` later would retroactively turn every function
     returning an Array into a do block.
   - No auto-`pure`. The trailing expression of a do block is already the
     monadic value (`Some(3)`, not `3`), so `do` never changes what an
     ordinary expression means. This matters more here than in Haskell, since
     a function body becomes a do block without anyone typing `do`.

   Answered: an empty or `?`-free `do { ... }` emits nothing at all. No
   `bind`, so no `Monad` obligation, so nothing for the monad to be ambiguous
   *about* -- it is exactly the block it wraps, and `do { }` is `Unit`. The
   question dissolved rather than being decided.

   Not doing: error conversion across a `?`. Rust needs `From<E1, E2>`, an
   MPTC, which single-parameter classes cannot express (the same homogeneity
   cost as design.md section 8.2's operators). Same error type, or convert by
   hand. Revisit if it proves a real ergonomic problem, not before -- no
   cargo-culting features in ahead of the evidence.

   Done, M12c. There is no fast lowering, and there is not going to be one.

   The "two lowerings" framing below was wrong twice over, and both
   corrections are worth keeping rather than deleting.

   The first: it conflated two axes. What M12 needed first was a more
   *general* lowering, for control-flow correctness -- and the naive closure
   lowering is the oracle only on the fragment where nothing crosses a `?`.

   - Naive: every continuation becomes a closure. Still the definition of
     what `?` means -- on straight-line code, where a `?` is exactly `bind`
     plus a lambda and nothing else is emitted.
   - General (M12c, done): a control construct containing a `?` is *lifted*
     into the monad, and a `return`/`break`/`continue` that crosses one
     travels as a value (`Flow`) because a value is the only thing a `bind`
     propagates. Escaping is not something a `bind` does, and for `Array` --
     continuation once per element -- there is nothing coherent an escape
     could mean. Written out longhand in design.md 6.9.

   The second correction is the larger one: *fast* was never an axis of the
   lowering at all. A "fast lowering" was going to be a second, `?`-aware
   translation, guarded by a closure fallback, differential-tested against
   the first. All three of those are now deleted, because the premise was
   wrong.

   Nobody does this. GHC desugars `do` exactly once, in GHC.HsToCore, to
   `>>=` applied to a lambda; the speed comes afterwards from general Core
   passes -- inline the instance's `>>=` (which is why IO/State bind carry
   INLINE), beta-reduce the now-known continuation, case-of-known-constructor,
   join points (Maurer, Downen, Ariola & Peyton Jones, *Compiling without
   continuations*, PLDI 2017). Scala's for-comprehension is `flatMap` plus a
   lambda and leaves it to the JIT; OCaml's `let*` is `bind` and leaves it to
   Flambda. Rust's `?` looks like the exception and is not one: its
   continuation is always the rest of the function, which is already the
   fallthrough, so it lowers to a `match` on `Try::branch` and no closure is
   ever built. That is the *shape inlining reveals* for a monad whose bind
   invokes its continuation at most once and does not escape -- not something
   a lowering has to decide up front.

   So: desugar.py stays the only lowering of `?`, and everything that was
   going to be the fast one moves to 7 as passes that know nothing about
   monads. See 7 for the three.

   Three obligations retire with it:

   - **The closure fallback is not a mode.** Capped generic code -- a `?`
     inside `fun f[Monad m](...)` that still projects `bind` out of a
     parameter, which coherence says nothing about -- is simply code the
     inliner could not fire on. An absence of an optimization, not a second
     path, and so not a shape anyone has to design.
   - **The differential test is retired.** One lowering has nothing to be
     tested against. Validation is coretc.py re-run on each pass's output
     plus the goldens, which is the M14b pattern: same source, same output,
     different Core underneath. (M2.5's criterion asked for two
     known-equivalent implementations of one specification; there is now one.)
   - **Nothing needs marking in the sugar.** `EQuestion` and `EDo` are still
     consumed by desugar.py rather than deleted from ast.py, but the reason
     given there -- keeping a sugared tree to lower a second way -- has
     lapsed. ast.py's note that `?` "will want lowering to join points
     directly" is superseded by this entry.

   What survives unchanged is what a fast `?` owes, stated exactly (delta
   47): reproduce the *bind chain* -- how many times a continuation is
   invoked and in what order -- and not the `Flow` encoding. `Flow` is not
   part of `Monad`; it appears in no signature and an instance can neither
   see nor match on it. That is what licenses 7's passes to erase it.

   Still true, and now 7's problem rather than 4's:
   - Whatever form mutable locals take across a join point has to reproduce
     capture semantics exactly, since that is the spec. Since M13c a `var` is
     an explicit reference cell in Core, so what has to be reproduced is
     written down rather than implied by the evaluator's scope chain.
   - M14 is what gives the inliner something to fire on. In `question.tl`
     there are no `.bind` projections left at all: every one is a top-level
     binding by name, specialized to the element types as well as the monad
     (`%inst.Monad.Data.Option#Option#bind@Int,Int`, ten of them). Not a
     projection, not an indirect call, monomorphic in its argument types --
     an ordinary inliner's ordinary case.

5. typed Core IR
   Done, M13a/b/c. The description below held up exactly: giving the
   elaborator a datatype is what made evidence checkable rather than trusted,
   and a dictionary is now an ordinary value passed as an ordinary argument.
   SSA stayed below it, untouched.

   What it took, in the order it had to happen:
   - M13a: inference stops discarding what it computed. Every expression's
     type, and the *type arguments* every use site instantiated its scheme at
     -- `instantiate_qual` had always built the second and thrown it away,
     because until there was something to lower to, nothing asked.
   - M13b: `core.py`, `lower.py`, `coretc.py`. A class is a record type, an
     instance a top-level binding, evidence an ordinary term. The checker
     runs unconditionally, because a check nobody runs does not make evidence
     checked.
   - M13c: the evaluator runs the Core. Ninety-one goldens, not one output
     changed.

   Three things the checker caught the moment it existed, none of them
   visible in any program's output: a default method is elaborated once
   against the class variable and shared, so copying it per instance put `a`
   where `Int` belonged; a method body -- and any body with a complete
   signature -- is checked against skolems, so its recorded types name
   constants where the declaration names variables, and nothing recorded
   which was which; and a recursive call, monomorphic to inference, still
   needs its type application in System-F. That is the milestone paying for
   itself on the day it landed.

   Two things it made visible rather than fixed, both now recorded in the IR
   rather than in the interpreter: a `var` is a reference cell, so capture by
   reference is a property of the term; and a parameterised instance's
   dictionary is rebuilt per request now that the memo table is gone, which
   is correct, terminating, and work 6 should remove.

6. monomorphization / specialization
   Done, M14a/b/c/d. Was missing from this list, and delivered all three things
   it was asked for: dictionary passing is cheap, the per-request rebuild 5
   left behind is gone, and `?`'s fast lowering has something to inline in
   ground code (see 4 for what it still does not have).

   The fact that shaped the whole design, and was verified rather than
   assumed: Turkey admits polymorphic recursion, so monomorphization cannot
   terminate in general. `fun depth(x : a, n : Int)` recursing at `Pair a` is
   the probe, and adding `instance [Show a] Show (Pair a)` makes the dictionary
   chain infinite too, so specializing on dictionaries instead would not have
   escaped it. So the pass is **partial** by decision: past a cap the call site
   keeps its type application and calls the generic binding, which is never
   removed. Every program that compiled before compiles now; some are only
   partly specialized.

   The cap used to warn when it tripped, and no longer does. The warning was
   arguing that a program whose performance depends on a budget is a program
   whose performance nobody was told about -- which assumed the cap was a
   *failure to compile properly*. It is not. **Turkey does not guarantee
   monomorphization.** What the cap refuses is an optimization; 9's layout-keyed
   sharing compiles what is left, and 7's passes may recover much of the rest by
   inlining and constant propagation, with no promise about how much. A binding
   that stays polymorphic is not a binding with something wrong with it, so
   there is nothing to say about it. The budget stays; the diagnostic goes.

   What it took:
   - M14a: one copy of a generalized binding per type it is used at. A ground
     instance application becomes one top-level record rather than a rebuild
     per request.
   - M14b: the evaluator runs the specialized program. The goldens are the
     differential test -- same source, same output, different Core underneath.
   - M14c: a method selected from a ground dictionary becomes a name, which
     coherence (delta 43) is what makes sound; and what nothing reaches is
     dropped, which is where the pass stops being an addition.
   - M14d: the first two make work for each other, so they run twice, on one
     shared budget. The budget had to be shared rather than per-round or the
     cap would have stopped being a bound -- N rounds would have granted 32N
     copies -- and sharing the memo is what stops a second round rebuilding
     the first round's copies under a disambiguated name.

   Two rounds and not a fixed point, deliberately: a third round changes
   nothing measurable, and "iterate until nothing changes" is a promise about a
   number polymorphic recursion does not let this pass make. Raising the round
   count is a one-line change that cannot break the bound.

   On tests/programs/dicts.tl: dictionary projections 65 -> 14, and 77
   top-level bindings -> 62, after a pass whose only job is to make copies.
   What remains is inside the bindings that are still genuinely polymorphic.

7. optimizations
   A consequence of 5 and 6, not a milestone of its own -- but it absorbed 4's
   fast lowering, so it is now where the `?` work lives. Choosing the IR shape
   is still the decision; the pass list follows from it.

   The shape decision, made: **join points go in Core, not in an SSA IR below
   it.** Item 5 deferred them -- "control transfers are still nodes typed `!`
   rather than jumps to join points ... worth doing, under item 7, against a
   Core that already exists" (core.py) -- and design.md 405 says the same.
   That deferral is now cashed, and item 5's "SSA belongs below this, in the
   backend" still holds: SSA is 10-12's business. Join points are not SSA. They
   are a distinguished form of `let` whose bound lambda is only ever
   tail-called and never escapes, which is the *Compiling without
   continuations* design, and GHC put them in Core for the same reason: a
   separate IR below Core is not where the information is.

   Done, M15a: the nodes and the rule. `CJoin` and `CJump` are in Core, the
   checker has a rule for each, and the evaluator runs them -- and nothing
   emits one yet, so every golden is byte-identical and the only evidence the
   milestone exists is `tests/test_joins.py`, which builds the terms by hand
   and mostly asserts that the wrong ones are rejected.

   They are separate nodes rather than a flag on `CLetRec` with `CApp` for the
   jumps, because the restriction is the point: a walker taught nothing about
   `CJoin` raises, and a walker taught nothing about a flag quietly treats a
   join point as a closure and is right. That is the shape of trust item 5 was
   written to remove.

   Tail position is **derived and not tested for**. The checker carries a
   second environment of join names beside the term environment and passes it
   down only into tail positions -- an `if`'s branches, an alternative's body, a
   `let`'s body, a join's body and rest -- so every other recursion gets an
   empty one and a jump from an argument, a scrutinee or inside a lambda simply
   fails to find a name that is lexically right there. There is no
   tail-position predicate to write and none to get wrong. The same move
   `CAlt` already makes by deriving what a pattern binds instead of restating
   it.

   That the lambda case falls out of this is what makes the evaluator's
   `JumpSignal` safe: a jump cannot escape into a closure, so catching by name
   on the Python stack is lexical scoping and not a dynamic approximation of it.

   Done, M15b: `turkey/joins.py` finds them. A `let`-bound lambda whose every
   mention is a saturated tail call and which never escapes becomes a `CJoin`,
   and its mentions become `CJump`s; a tail-recursive local becomes a recursive
   one, which is a loop nothing in the surface program called a loop. There is
   a `turkey opt` beside `core` and `mono`, and a `.opt` golden family beside
   `.core` and `.mono`.

   Which positions are tail positions is now stated once, in `core.TAIL_FIELDS`,
   and read by the pass and by the checker's rule -- so the two cannot drift on
   the fact they both depend on. Where they could still drift, they are compared
   automatically: `driver.check` runs `coretc.check_program` after the pass on
   every program in the suite, and calling a position a tail when the rule does
   not means a jump with nowhere to go.

   The optimized Core is the program that runs, for M14b's reason: a pass whose
   output is only ever inspected is a pass nothing tests.

   It finds nothing at all in the rest of the suite, and that is the honest
   answer rather than a shortfall. The lambda a `?` builds is an *argument* to
   `bind`, so it escapes by construction, and no analysis can call it a label
   until inlining has put it in tail position. M15c and M15d are what give this
   pass something to chew on; `tests/programs/joins.tl` is what exercises it in
   the meantime.

   Done, M15c: `turkey/opt.py` -- inlining, beta, case-of-known-constructor,
   and the dead `let` the other three leave behind. One traversal rather than
   three, because they feed each other: inlining puts a lambda in a function
   position, beta binds a parameter to a constructor, that selects a branch,
   and the branch exposes the next call.

   Termination is **structural, not budgeted**, which is the difference from 6.
   The call graph comes out of `core.names_of` and `deps.sccs`, and one binding
   per cycle is a loop breaker and is never inlined; the choice within a
   component is the lexicographically first, arbitrary but stable, because a
   golden depends on it. A size limit on the *reduced* body bounds the growth,
   and bodies are memoized -- without that, a call chain re-reduces its callees
   once per path that reaches them, which was measurably the entire cost.

   Three things it must not do, and each was found by the suite rather than by
   thinking:

   - **A body holding `return` is not inlined.** A transfer names its target by
     where it is, so `return 0` dropped into a caller returns from the caller.
     This is the debt M15e settles: once the transfers are jumps, they name a
     join point and travel with the term.
   - **A `match` fires only on a scrutinee that is a *value*.** Selecting a
     branch discards the arms not taken and, under a wildcard, the scrutinee --
     and discarding `Some(launch())` is a different program.
   - **A substituted argument must not be captured.** `Array`'s `bind` walks
     its elements in a `for`, and a binder analysis that did not count the loop
     variable put the continuation inside the scope of the element it was to be
     applied to. That analysis is now driven by field name rather than by a case
     per node, so a node added later cannot fall outside it by accident.

   Done, M15d: case-of-case, plus the three small rules that turned out to be
   its precondition. `tests/programs/question_opt.tl` is the milestone in one
   file: a two-`?` function over `Option` comes out as nested `if`s with no
   call, no lambda, no `match` and no intermediate `Option` -- which is what
   Rust's `?` compiles to and what a C programmer writes by hand. Nothing that
   produced it knows what a monad is.

   The three preconditions are worth naming, because each was a reduction the
   pass declined for a reason that looked right:

   - **Free names, not mentioned names.** The capture guard read every name a
     term mentioned. A `?` continuation contains `let x = ... in ...` and
     `Option`'s `bind` calls its first parameter `x`, so the guard refused to
     inline `bind` at all. It reads free variables now.
   - **Re-walk after a reduction.** Substituting the continuation for a
     parameter puts a lambda where `bind`'s body had `f(x)` -- a beta redex in
     a subterm the traversal had already been past. Reducing only at the root
     left every chain one beta short of the point.
   - **Bind a constructor's arguments; do not demand a value.** Selecting a
     branch discards the constructor application, so the first version fired
     only on a scrutinee that was already a value. That also declined on
     `Some(n / 2)`, which is every `?` over `Option` there is. Binding the
     arguments in order, including the ones the pattern ignores, keeps the
     effects and lifts the restriction.

   M16c reaches the first thing this did not. `bind` and `pure` are methods, so
   their call sites remain type applications over the method's own quantifiers
   however ground the dictionary is. The inliner now beta-reduces that type
   application in place before doing its ordinary term beta reduction. This
   is not monomorphization: it makes no top-level copy, needs no groundness
   restriction, and therefore accepts the phantom variable in a lifted loop's
   uninhabited `Brk` slot. The small Option and Either methods disappear from
   `question_control.tl`; Array's `bind` and Flow across joins do not. M16d now
   handles the non-recursive join boundary; the recursive and large-method
   cases remain tracked below rather than hidden behind that first obstruction.

   The passes make programs *bigger*: on `question.tl` the specialized Core
   grows about half again. That is what an inliner is, and item 7 said as much
   before it was built -- the tree-walking evaluator cannot show the win, and
   the payoff is 9's. Case-of-case itself is roughly size-neutral: it costs
   fifty-odd nodes on `question.tl` and saves twenty on `monads.tl`.

   Done, M15e: `turkey/loops.py`. The four loop forms become one recursive
   join point and its jumps; `return`, `break` and `continue`, which named
   their target by *where they were*, become `CJump`s that name it; and
   `CForIn`'s `iter`/`next` elaboration -- the "a later pass should" in
   `core.py` -- is that pass. Across the suite, no loop node and no transfer
   survives into the optimized Core: 517 join points and nothing left.

   The debt it settles is M15c's. A transfer that names its target by position
   is a term that cannot be moved, so the inliner refused every body holding a
   `return` -- one function in eight. A jump names a join point and travels
   with the term, so the refusal is gone, and the M15c test that asserted it
   now asserts the opposite.

   Written as one rule rather than four: `while c { b }` *is*
   `if c { b; continue } else { break }`, so each form is expressed in ordinary
   Core with the transfers still in it and handed back to the same converter.
   The C-style `for` is the one genuine difference -- `continue` runs the step
   before the test -- and it gets a third join for the step.

   Partial, and it counts its refusals. A transfer inside a call's argument
   needs the arguments beside it bound in order, since the evaluator is strict
   and left to right; `bf.tl` writes exactly that and `anf` handles it. A shape
   with no rule leaves the binding untouched rather than being guessed at,
   because a control-flow rewrite that is subtly wrong is a wrong answer rather
   than a rejected term. The count is zero and the suite asserts it.

   What it left: the nodes were still in Core. Nothing that ran held one, but
   `lower.py` still emitted them, so `coretc.py` and `eval.py` still had to
   know them. M16a is that debt.

   Done, M16a: the loop forms are lowered, not collapsed. `turkey/lower.py`
   builds `CJoin` and `CJump` straight from the AST, and `CWhile`, `CLoop`,
   `CForC`, `CForIn`, `CReturn`, `CBreak` and `CContinue` are deleted from
   `core.py` -- with their rules in `coretc.py` and `eval.py`, the
   `ReturnSignal`/`BreakSignal`/`ContinueSignal` exceptions, and
   `turkey/loops.py` entire. A term that names its control target by *where it
   sits* is now unrepresentable rather than merely unused, which is the
   difference between a claim about the suite and a claim about the IR.

   The cost the shape decision was meant to bound did not materialize: no
   continuation parameter runs through the walker. `Scope` carries three join
   names, `expr` gains one branch -- a subtree holding a loop or a transfer
   goes to the converter, everything else takes the walk it always took -- and
   the operand case installs its lowered operands in a by-identity map and
   then calls the node's ordinary rule, so `_lower_ECall` neither knows nor
   needs to know that an argument arrived as a jump.

   Two things fell out. `CForIn`'s cursor elaboration now happens *before*
   `coretc.check_program` instead of after it, so design.md 6.5's elaboration
   is checked rather than trusted. And `opt._transfers` stopped being a node
   test and became a free-join-name test -- whether a jump names a target
   bound outside the term being moved -- which is the reduction the join
   points were for.

   M15e's partiality is gone with the fallback: there is no loop node to leave
   behind, so a shape with no rule is `Unsupported` at compile time rather
   than a binding quietly left alone, and compiling every program in the suite
   is how that is noticed. `Checked.unlooped` and the count it carried are
   deleted.

   It also turned up a latent bug in `coretc.bind`, which compared a binding's
   derived type against its declared one *after* restoring the equation scope,
   so `want` never reduced under the binding's own equations. It went
   unnoticed because every early `return` used to make a body bottom, and
   bottom is compatible with anything.

   Done, M16b: a lifted loop's helper is not generalized. `desugar._loop`
   lifts a loop into a recursive helper whose `Flow` `Brk` slot is uninhabited
   by construction -- `round_again` turns a `Brk` into the *enclosing* `Fall`
   -- so inference quantified over a variable nothing could ever solve, and
   `mono` only specializes at ground instantiations. `ast.FunDecl` gains an
   explicit flag rather than a check on the `%` prefix, which `desugar.py`
   documents as a collision-avoidance guarantee and nothing else; `desugar._fun`
   is its only writer and `infer.build_definition` honours it. The
   justification is that the helper has exactly one use site, so there is
   nothing for generalization to buy.

   `question_control.tl`'s optimized Core goes from nine `forall`s to none and
   loses 142 lines. Its 245 `Flow` constructors do not move, and that is the
   result: the hypothesis this milestone was built on was wrong, and the M15d
   paragraph above now says so. What holds them up is method-level
   polymorphism, which is not something specialization removes.

   Done, M16c: local type beta reduction. A devirtualized method is represented
   as a `CBind` with type binders and a `CLam` value, not necessarily as a
   literal `CTyLam`; a saturated `CApp(CTyApp(CVar(...), targs), args)` now
   substitutes those type arguments through the lambda and enters the same
   bounded inliner as a monomorphic call. Instantiated bodies are memoized by
   name and structural type key, and the existing loop breakers remain keyed
   by binding, so accepting non-ground type arguments creates no new route to
   polymorphic-recursion divergence.

   On `question_control.tl`, type-applied calls fall from 182 to 77 and printed
   `Flow` type occurrences from 219 to 86. Actual `CCon` constructions fall
   from 105 to 97. The old number 245 counted every printed Flow tag, including
   match patterns; after inlining exposes more matches that number rises, so it
   is not a constructor-allocation metric and is no longer used as one.

   Done, M16d: specialize join arguments that arrive as known constructors.
   Case-of-case deliberately puts a shared continuation in a `CJoin` to avoid
   multiplying it by four, then jumps to it with values such as `Fall(x)` and
   `Ret(r)`. A non-recursive single-use join is beta-reduced when moving its
   body cannot capture a free name. A shared join is copied once per useful
   constructor signature, not once per edge: constructor fields and unknown
   arguments become the specialized join's parameters, its body rebuilds the
   known value, and ordinary case-of-known-constructor does the rest. A copy
   must shrink and remain at or below `JOIN_SPECIALIZE_LIMIT` 40.

   The representation determines the staging. The first reduction exposes
   local continuations; discovery turns them into joins; one more reduction
   sees the constructor-valued jumps. This also exposed an over-conservative
   `let`-to-match capture guard: a match pattern scopes over its arm, not its
   scrutinee, so an equally named free variable in the producer cannot be
   captured there. Removing that refusal is what lets the producer reach the
   join in the first place. On `question_control.tl`, type-applied calls fall
   again from 77 to 49 and actual Flow `CCon` constructions from 97 to 42.

   Done, M16e: recursive join result fusion. A lifted loop's recursive join
   genuinely returned `Option (Flow ...)`, and a loop breaker correctly
   prevented local inlining from unfolding it. The result consumer is now
   distributed over the yielding tails of the recursive join's body and entry,
   while back-edge jumps remain untouched in tail position. The join therefore
   answers with the consumer's result type directly: a worker/wrapper-style
   multi-exit transformation, not another local case-of-known-constructor rule,
   and one which knows neither `Flow` nor a particular monad.

   On `question_control.tl`, all ten recursive joins lose `Flow` from their
   result type and actual Flow `CCon` constructions fall from 42 to 33. A
   20,000-iteration lifted loop pins that the rewrite retains stack-safe join
   recursion as well as the result. Capture is handled by declining when a
   consumer's free name would move under a binder, as in the other local
   reductions.

   Done, M16f: cost large inlining after call-site reduction. The ordinary
   `INLINE_LIMIT` remains 40. A body up to a separate hard ceiling of 160 may
   be applied to the call's known arguments and reduced speculatively, but the
   inline is committed only if that residual comes back under 40. Large
   speculation does not nest. Thus a large method with a cold constructor arm
   can inline when a known argument deletes that arm, while an unknown call to
   the same method remains a call; the test pins both sites.

   `Array#bind` is the refusal that motivated the rule. Its reduced body is 61
   nodes after M16e, but its eight call-site residuals range from 76 to 179, so
   none is admitted. Forcing the blanket limit high enough removes the calls
   but grows `question_control.tl` from about 1,855 to 2,645 Core nodes and
   raises actual Flow constructions from 33 to 41. A warm generated-Python
   probe over a ten-element bind showed no material execution improvement.
   The backend evidence and the size model therefore agree: retaining those
   calls is the optimization decision, not an unfinished exception.

   Three passes, none of which knows what a monad is:

   - **Inlining.** A `CVar`, directly or under a `CTyApp`, naming a top-level
     binding with a known, small RHS. M14c is what made instance methods into
     such names and M16c instantiates their own quantifiers locally.
   - **Beta and case-of-known-constructor.** The continuation lambda
     disappears by reduction once its call site is known. This is where a `?`
     over Option becomes the `match` Rust writes by hand.
   - **Join-point discovery.** An analysis marking `CLet`-bound lambdas that
     are only tail-called and never escape. Not `?`-specific: it is what the
     four loop forms and `CReturn`/`CBreak`/`CContinue` need anyway, and
     collapsing those four into one is the other half of what 5 deferred here.

   Ordering, and it is the one thing that is not free: **join points around
   case-of-case's sharing boundary.** Inlining `bind` does not by itself remove
   `Flow` -- that needs case-of-case, to see that a `Flow` built in one branch
   is scrutinised downstream, and case-of-case is exactly the pass that
   duplicates continuations and blows up code size. Join points are the known
   answer to that, and are most of what the 2017 paper is about. Reduction,
   discovery, then a second local reduction is the concrete order: the first
   pass exposes continuations, discovery preserves their sharing, and the last
   pass specializes known incoming tags without copying per edge.

   The old evaluator was a tree-walker over name-keyed environments, so an
   inlined `bind` cost it a dict lookup either way and the goldens could not
   show a difference. Item 8 changes that: the same checked optimized Core now
   becomes Python locals, calls and labels, so these passes have a measurable
   payoff before the native runtime exists. Item 9 remains the scale test.

8. Python source backend
   Done, M17. `turkey run` compiles optimized Core to deterministic internal
   Python source, compiles that source in memory, and executes it. Ordinary
   Core values are Python locals and direct calls; type abstraction and
   application erase; constructors, records, arrays and cells reuse the small
   existing runtime. There is no supported source-file artifact and no cache.

   Each lambda and the top-level initializer lower to numbered basic blocks.
   `CJoin` is a block and `CJump` evaluates its arguments left to right,
   assigns the block parameters simultaneously, and continues one dispatcher
   loop. A recursive join is therefore stack-safe without an exception or a
   Python call. Lambdas snapshot ordinary captured locals in defaults, while
   recursive and top-level names use Python closure cells; that distinction is
   what preserves the fresh parameter scope of each loop iteration.

   The tree-walking evaluator remains as an oracle, not a fallback. Every
   successful conformance program runs through both in `test_pygen.py`, while
   the ordinary goldens reach only generated Python through `turkey run`.
   The non-CI benchmark separates generation, Python compilation and warm
   execution. On the landing probe, the 200,000-iteration join loop was 9.1x
   faster and `bf.tl` 8.0x faster than the evaluator, past the 3x gate.

9. bootstrap compiler (same frontend, IR, optimizations), emitting C
   FINDINGS.md is the running list of what this exercise turns up -- language
   bugs, design costs, ergonomic friction, and library pieces that were missing.
   Keeping it as work proceeds is the point: the interesting part of a papercut
   is the moment it bites and what was being written at the time.
   Still ahead of the native backend work, and still the first real program in
   the language -- the only forcing function that finds papercuts at a scale
   test.tl cannot. What changed is the artifact: a *compiler*, not an
   interpreter, and one with a real target from the first line.

   An interpreter would exercise the same language surface and leave the
   compiler's hardest question -- what a Turkey value is on a machine --
   untouched, and would be thrown away when 10 through 12 arrive. So the
   bootstrap emits C, which is a decision about all four of these:

   - **Target C.** `CJoin` and `CJump` are labels and `goto` with no
     relooping, libc is the file I/O and the argv, and generated C is
     diffable when it is wrong. WASM needs a linear-memory layout, an
     allocator and a relooper before it prints a line; it is the second
     target, and the thing that proves the Core-to-target boundary is real.
   - **No intermediate cgen.py.** The self-hosted compiler is the first thing
     that ever emits C.
   - **Full Turkey.** It accepts the whole language -- classes, families,
     HKTs, `?`, mono, opt -- and consumes `turkey/lib` as-is rather than
     reimplementing it. That constrains the accepted language, not the
     delivery order: the milestones stage internally and each is diffed
     against the Python implementation.
   - **Unboxed primitives, on a bump arena that never frees.** Section 6.2
     makes representation opaque and forbids the *type system* from
     influencing it, which is precisely the licence for the backend to choose
     one: an `Int` is an `int64_t`. What makes that total rather than
     best-effort is 10's layout-keyed sharing, which therefore lands here --
     see below. Memory is a pointer bump and no collector, because a compile
     is a short batch process; if a self-compile does not fit, that
     measurement is the argument for the collector, and it is a better
     argument than the guess this document would otherwise be making.

   The Python implementation is not replaced. It becomes what eval.py became
   after M17: the differential oracle, and the second host whose agreement
   M26 checks.

   Done, M18: the floor. `print`, `write` and `error` were the whole of the
   language's contact with anything outside itself, which is to say a Turkey
   program could not read its own source and so could not be a compiler.
   Six primitives (`args`, `fileCanRead`, `readFileBytes`, `writeFileBytes`,
   `stderrWrite`, `exit`), `System.Env` and `System.IO` over them, and `--` on
   `turkey run` to hand a program its own command line. Both file doors speak
   bytes, so `readFile` answers `Option String` through the checked
   constructor rather than hiding the UTF-8 validation inside a read.

   With it: the opaque `String.Index` PRIMITIVES.md 4.3 held in reserve,
   shipped now because a lexer is what needs it; `Int.parse`, whose
   accumulator runs negative so that `minValue()` parses; ASCII classification
   on `Data.Char`; `Data.Array`'s `at`/`last`/`swap`/`slice`/`indexOf`/
   `contains` and a stable merge `sort`; `Data.Map`'s `contains`/`getOr`/
   `update`/`keys`/`values`/`entries`; `Data.Set` over `Map k Unit`; and
   `String.lines`/`words`. Every one of these has to be written a second time
   in the C runtime, which is what keeps the list short.

   And the recursion limit, which was a real cap rather than a detail: the
   generated program runs on a thread with a 512 MiB stack, because CPython's
   thousand frames is a fact about the host and an AST walk passes it on an
   ordinary file. The C backend's answer is the same shape.

   The first papercut is already recorded, and it is the kind item 9 exists to
   find: an instance's associated family may be defined as a family applied to
   a *variable* of the instance head but not to a concrete type, so a wrapper
   type cannot reuse its inner type's cursor abstractly and `Data.Map` has to
   export `MapCursor` for `Data.Set` to name. The restriction is what makes
   family reduction terminate, so the export is the cheaper side -- but it is
   a real cost of the design, found by writing the second program that ever
   wrapped a container.

   Ahead, in order, each diffed against the Python implementation over
   `tests/programs` and `turkey/lib`:

   Done, M19: the lexer. `boot/Turkey/{Source,Diag,Token,Lexer}.tl` and
   `boot/Main.tl`, and `boot tokens` agrees with `turkey tokens` on every token
   of all 79 Turkey files in the repository -- the conformance programs, the
   standard library, and `boot/`'s own source, which is the one that has to
   work for any of this to bootstrap.

   The diff needed a format before it needed a lexer. `turkey tokens` printed
   Python's `repr` of each token value: the quote it picks depends on the
   contents, its escapes are Python's, and its floats are `repr`'s -- none of
   which another implementation can reproduce, and all of which would have made
   "the two agree" mean "Turkey imitates CPython". It now prints a canonical
   `line:col KIND payload`, where the float spelling is PRIMITIVES.md 3.3's and
   the escapes are design.md 2.1's. Neither implementation can be right merely
   by being the host.

   Two deliberate divergences, both toward the spec rather than away from it.
   Python asks `str.isalpha` and `str.isdigit`, which are Unicode-wide, so a
   Devanagari digit would start a numeral there; design.md 2.1 says `[0-9]`,
   and that is what the port asks. And an integer literal outside `Int`'s range
   is a lex error rather than an unbounded token, which is what PRIMITIVES.md
   1.3 requires and what the Python lexer still does not do.

   Two more papercuts, and one of them was a *bug* rather than a design cost:

   - **A module's own declaration lost to an import in its export list.**
     `modules._exports` classified an uppercase export by asking whether the
     name was a class *anywhere in scope* before asking whether the module
     declared a type by it -- so `Data.String`'s export of `Index` re-exported
     `Std.Classes`'s `Index` class and its own `Index` type was invisible from
     outside. Own declarations shadow imports everywhere else; now they do here
     too. Nothing in the suite could have caught it, because nothing before
     `boot` named that type from another module.
   - **A qualified type name resolves after all.** This list first said it did
     not -- `String.Index` was "unknown type" -- and that was the export bug
     above, fixed in the same commit and not re-tested afterwards. One bug's
     symptom read as a second bug. `String.Index` works, from a module with no
     imports at all.

   Done, M20: the parser. `boot/Turkey/{Ast,AstDump,Parser}.tl`, and `boot ast`
   agrees with `turkey ast` on every node of all 82 files -- 39,791 lines of
   tree, spans included. Spans are in the dump on purpose: a parser that builds
   the right shape from the wrong token reports every later error in the wrong
   place, and this is the cheapest stage at which to catch that.

   `turkey ast` printed the dataclass `repr`, so it needed the same treatment
   the token dump got at M19 and now prints an indented tree with three rules:
   scalars are atoms on the node's line, sub-nodes are children below it, and a
   list is a `list N` line while an absent optional is a `none` line -- both
   occupying the child position they would have, so a node's arity is fixed.

   The two representation decisions this milestone was told to take up front,
   taken:

   - **A mutable record wrapping an immutable variant.** Python's nodes are
     mutable dataclasses and `desugar.py` rewrites them in place, so everything
     holding one sees the rewrite. Turkey's ADTs are immutable and its
     single-variant records are the mutable ones, so each syntactic category is
     a record carrying a variant, and M21 will assign a new `kind` rather than
     build a new node.
   - **An integer identity.** `typed.py` keys every expression by Python object
     identity; Turkey has no identity hash, so the parser stamps a monotone
     `id` on every node it makes and M22's tables will key on that.

   One thing genuinely differs, and the language forced it. Python backtracks by
   *catching* a `ParseError` twice -- deciding whether a method is a signature,
   and whether a `for` is the `in` form or the C-style one. Turkey has no
   exceptions, so neither speculation can be a failed parse that is undone.
   Both are decided instead by a token scan for the one thing that separates the
   readings: a definition has an `=` or a `{` after its parameter list at depth
   zero and a signature has neither; a `for ... in` has an `in` at depth zero
   before its body. `_rhs_has_alternatives` was already such a scan in the
   Python, so this is the shape that file was reaching for rather than a
   workaround -- a speculative parse decides by failing, and a scan decides by
   looking. The standard library is full of both constructs, so agreeing over
   the corpus is what says the two readings coincide.

   Two more papercuts, both small and both about names:

   - `hiding` is a reserved word, so it cannot be a *field* name --
     `ImportDecl.hiding` in the Python has to be `hidden` here. `export` is
     reserved too and the grammar never uses it. Reserving a common word costs
     a name in every record a program writes.
   - A branch ending in `expect(...)` answers a `Token` while its sibling
     ending in a `while` answers `Unit`, and the two do not unify. Thirty-eight
     call sites wanted a statement rather than an expression, which is what
     `skipToken` is. A language where a block answers with its last statement
     makes "call this and discard the result" a thing that has to be said.

   Done, M21: modules, resolution and the `?`/`do` lowering.
   `boot/Turkey/{Prims,Prelude,Modules,Resolve,Desugar}.tl`, and `boot desugar`
   agrees with `turkey desugar` on every node of every module of every entry
   program -- 376,529 lines. The dump is M20's tree under a `module NAME` line,
   for *every* module of the program rather than the entry one: what resolution
   does to a module depends on what it imported, so the entry alone would check
   the interesting half against nothing. A library module cannot itself be an
   entry -- it resolves its own imports against its own directory -- so the
   entry list is the conformance programs plus `boot/Main.tl`, and between them
   they pull in the whole of `lib/` and the whole of `boot/`.

   What that adds over M20 is exactly what the two passes change: every name is
   internal, every bracket is an `Index` method call, and every `?` is a `bind`.
   The generated binders are in the dump, so the two implementations are pinned
   to the same *numbering* of `%k1`, `%loop1`, `%fell1` and the cursor names --
   not merely to the same shape.

   Writing the port found two miscompiles in the Python, in passes the suite
   already covered well:

   - **The inliner captured a caller's variable in a callee's parameter.**
     `opt._apply_names` substitutes a value argument into the callee's body and
     let-binds the rest, and checked the substitution against the binders of
     that body -- not against the `let`s it was about to wrap around it. So
     `internal(name, c.name)`, where `name` is a caller's local and also the
     callee's second parameter, bound `name` around the substituted `name` and
     the body read the field twice. It needs a caller's local and a callee's
     parameter to share a spelling plus a value argument for the other
     parameter; `Turkey.Modules` is the first code that ever wrote it. The fix
     is a fixpoint: a parameter that becomes a `let` disqualifies substituting
     anything mentioning it, and disqualifying one makes it a `let` in turn.
   - **A `do` block as an entire function body was never lowered.**
     `Desugarer.walk` replaces a `do` rather than rewriting it, so its answer
     has to be taken, and two callers dropped it. `fun f(o) = do { let x = o?;
     Some(x) }` kept its `?` into `deps.free_names`, which crashed with an
     internal assertion. That one came from reading the pass closely enough to
     port it, which is a different kind of reading from using it.

   Two things the language forced, both recorded in FINDINGS.md:

   - **No reflection.** The Python writes its four scanners -- and its
     transparent walk, and its bracket lowering -- as generic walks over the
     dataclass fields, so a node kind added later cannot be missed by one of
     them. Here `Turkey.Desugar.children` is that enumerator written out once
     and shared, and the safety property is gone: a node kind added to
     `Turkey.Ast` and forgotten there is missed by all four scanners at once.
     The mitigation is the corpus diff, which notices the moment any file
     contains such a node.
   - **No function identity.** `if k is not self.fall` is how the Python
     decides a loop is in statement rather than value position. There is
     nothing to compare a Turkey closure against, so `Cont` is a variant here:
     `KId`, `KFall`, `KPure` and `KFn`, only the last a real closure. That is
     the better spelling -- `KFall` says what the continuation is, where a
     bound method compared by identity said only which object it was.

   `Ast.Program` now carries the parser's id counter on, because desugaring
   writes nodes of its own and they need ids from the same supply; a second
   counter starting at zero would collide with every node already in the tree.

   - M22, inference in Turkey. `boot types` against `turkey types`.
   - M23-M24, Core, mono and opt in Turkey, against the `.core`/`.mono`/`.opt`
     goldens. Two details are ports rather than approximations because a
     golden depends on each: mono's *shared* budget across its two rounds
     (M14d) and opt's lexicographically first loop breaker (M15c).
   - M25, the C runtime and `Boot.Cgen`. Six layouts -- I64, F64, U8, U32,
     VOID and PTR -- read off the Core type. `Array Byte` comes out packed and
     `Bool` comes out a bare tag by layout rather than by name, which is what
     PRIMITIVES.md 2 and 6 ask for. Every golden compiled by `cc` and run.
   - M26, self-hosting. stage1 under Python builds tc2; tc2 builds tc3. The
     ordinary fixpoint is stage3 against a fourth stage; the *stronger* check
     is stage2.c against stage3.c -- one Turkey program compiled by two
     different hosts, which is what catches a divergence between generated
     Python and generated C.

10. runtime: GC, closure representation, boxing
   Was missing from this list, and is the hard part of native compilation --
   not LLVM. Today everything is a Python object: RecordObj has reference
   semantics, ConValue is immutable, ArrayObj is mutable. None of that has a
   memory answer yet.

   **Layout-keyed sharing** is delivered by 9's C backend rather than here,
   because unboxing is what needs it; what stays in this item is the
   collector. The reasoning is unchanged and is kept here because this is
   where it was worked out. It is what makes 6's cap safe to be silent
   about. 6 specializes by *type* and cannot be total, because Turkey admits
   polymorphic recursion and the set of types a binding is used at can be
   infinite. So below it, specialize by *layout*: one compiled body per
   distinct layout of the type arguments, everything pointer-shaped sharing
   one. That pass is total, and for a reason worth stating exactly -- the set
   of layouts is finite by construction where the set of types is not. `Pair a`
   is pointer-shaped whatever `a` is, so `depth`'s infinite chain
   (`Pair Int`, `Pair (Pair Int)`, ...) collapses to a single layout key. The
   thing that diverged was the type index; the layout index cannot.

   So the tiers are: 6 specializes by type, on a budget, to enable
   devirtualization and 7's inliner; 10 shares by layout, always, for whatever
   6 declined. Exactly .NET's split -- one native body shared across every
   reference-type instantiation of a generic (`__Canon`), separate code only
   for value types, where size differs. Swift is the closest statement of the
   *policy*: generics compile unspecialized, via witness tables carrying size
   and alignment, and monomorphization is an optimization rather than a
   promise.

   What it costs, and it is not free: dictionaries. `Show (Pair Int)` and
   `Show (Pair (Pair Int))` share a layout but are different *values*, and with
   polymorphic recursion that chain is still infinite -- so a shared body
   builds its dictionaries as it recurses, which is exactly the dictionary
   passing 6 set out to remove, back in the region where the cap tripped. And
   7's inliner cannot fire there either, since `bind` is a runtime argument
   again. Layout sharing and devirtualization pull in opposite directions;
   the tiering above is what settles which wins where.

   Not a type-system change, and the earlier claim that it was is withdrawn.
   GHC needs levity polymorphism (`TYPE r`, `RuntimeRep`) and OCaml needs
   layouts because both *expose unboxed types in the surface language*, so a
   quantifier can range over things of different size and the kind has to say
   which. Turkey exposes none: `Int` and `Float` are ordinary types whose
   representation is this item's choice and nobody else's. So layout is a
   function of an already-explicit Core type, computed here, and `types.py`'s
   kinds do not move. The day an unboxed type becomes writable is the day this
   turns into a type-system question, and not before.

   What that policy does require: nothing type-directed at run time beyond
   dictionaries -- no reflection, no `typeof`, nothing that could observe which
   body it landed in. Coherence (delta 43) is what makes that hold, since the
   same instance is selected either way, so specialization can change speed and
   never meaning. It is the thing that would quietly break if reflection ever
   arrived.

12. DIY backend

Deferred probe: Beam. Its leverage is HKT-parameterized records (`Table f`,
`Table (Nullable Identity)`) plus MPTCs over rows. Turkey has HKTs and
families; nominal records, no rows, no MPTCs. Treat it as a type-system
requirements exercise -- attempt the port, and if it cannot be done, derive
the minimal missing feature set from what failed. Option and Either prove
nothing here; they typecheck today.

The thesis behind the order: prototype in Python to iron out the language
before building the hard-but-not-novel parts. Which is why 4 and 5 sit early
-- they are where the novel semantics live -- and 10 through 12 sit late.

Where it stands: 1 through 8 are done. 4 closed not by building its fast
lowering but by deleting it: the speed it wanted is general Core passes that
know nothing about monads, and those are 7 -- which now exists, in nine parts.
`CJoin` and `CJump` are in the IR with tail position derived rather than
tested for (M15a); discovery finds the labels already in a program (M15b);
inlining, beta, case-of-known-constructor and dead-`let` do the local
reductions with loop breakers for termination (M15c); case-of-case erases the
intermediate value, and a `?` chain over `Option` comes out as the nested `if`
that Rust's `?` compiles to (M15d); and the four loop forms are one recursive
join point, so `return` no longer names its target by where it sits (M15e).

M16a then took the loop nodes out of Core altogether by doing M15e's work in
the lowering, so seven nodes and `turkey/loops.py` are gone and a term that
names its control target by where it sits cannot be written; M16b stopped
generalizing the helper a lifted loop becomes; M16c taught the bounded inliner
to instantiate a type-applied lambda locally, including at non-ground type
arguments; and M16d carries known constructor tags through non-recursive joins
without copying their continuation per incoming edge. `question_control.tl`
now loses every small Option and Either `bind`/`pure` call and more than half
of its remaining actual Flow constructions. What remains is stated as M16e
and M16f where it lives: recursive loop joins still return Flow, and Array's
65-node `bind` is intentionally over the size limit.

M17 then made optimized Core executable as generated Python rather than a tree
walk. The evaluator remains a differential oracle, recursive joins are Python
loops, and the optimizer's wins now change wall-clock cost. M16e and M16f stay
tracked above: the backend gives the bootstrap probe a way to decide whether
they are worth doing rather than making their counts ends in themselves.

Next is 9, and it is a compiler rather than an interpreter: the first real
program in the language, the scale test for both the language and its new
execution path, and the thing that makes a Turkey value a machine value. M18
has landed -- the I/O, argument and string floor a compiler stands on, plus the
recursion depth to walk an AST -- and M19 through M21 with it: `boot` lexes and
parses every Turkey file in the repository, its own source included, to the same
tokens and the same tree the Python implementation builds, and loads, resolves
and desugars every module of every program to the same tree again. The whole
front end up to inference is now two implementations that agree. It has already
paid for itself twice, in an inliner miscompile and a lowering that dropped a
`do`, neither of which the suite could reach. What is left is M22 through M26.
